The builder's claims:

1. **`flow/fpga_profile.py` needs no change, and none was made.** AO made
   POLY_HI (core offset 0x11) an enable flop (`pe_core.sv:748-752`), not an
   eighth clock gate, and added no other gated register: the profile's
   seven per-core and four global conversions still match exactly, and it
   stages `--cores 3` and `--cores 2` without error. New
   `test_the_fpga_profile_leaves_no_clock_gate[3|2]`: after staging, the
   preprocessed sources (PE_FIFO_NO_CG, PE_FLOP_IMEM) clock only on `clk`,
   `sck`, `cs_n` (and `rst_n` as reset) and instantiate no `pe_cg` or
   `pe_latch`; the same scan of unstaged `src/` finds `cfg_gclk[0..6]`,

   new gated register the profile doesn't know fails it. (The brief asked

   not mine to edit.)
2. **`build.sh [--cores 2|3] [clk_div]`.** The default is `src/project.v`'s
   `PE_NCORES` (3); anything but 2 or 3, a clk_div other than 24, 25 or 30,
   an unknown option or two positionals is refused before any remote
   command. The staged `project.v` carries the asked count;
   `build_info.json` records `cores` and `clk_div`; Vivado and bootgen run
   under `nice -n 10` (`VIVADO_NICE`); `OUT_DIR`, `FETCH=0`. Tested with fake

3. **The clocks.** `CLKOUT2_DIVIDE(CLK_DIV / 8)`: 24 -> 3 (400 MHz, exactly 8x
   50 MHz, the crossings timed as 2.5 ns paths); 25 and 30 also give 3

   (`clk_div % 8 != 0`). The 3-core build is clk_div 24, 50 MHz. No change

The builder's caveats:
- One placement per build; the 2.5 ns SPI device crossings move by
  hundreds of ps between builds (+0.133 at 3 cores, +0.918 at 2 on the same
  path).
- The xmutil `unloadapp`/`loadapp` success formats are assumed (the stand-in
  prints `remove from slot 0 returns: 0 (Ok)` / `loaded to slot 0`); the
  script only rejects error lines and status, and relies on listapps'
  strict parse for the positive check. If the board's unloadapp prints an
  error word when the slot is already empty, the script stops (fail-closed);
  the orchestrator then does the load by hand.
- `install.sh`'s LOAD=1 path still runs unloadapp/loadapp/listapps in one
  ssh, as before; board_smoke.py never uses it.
- `hw_day.py` keeps its three 2-core apps; protoemu3c is not one of its.
- The study's KV260 section (docs/8x4-study.md) is left as the study wrote it.
